# 레퍼런스 메모 리치텍스트 — 설계 (4단계 완료 → 5단계 1번)

- 작성일: 2026-08-31
- 상태: 브레인스토밍 완료, 사용자 검토 대기
- 관련: `CLAUDE.md` "개발 단계 — 5단계 메모(스티키노트)"

## 배경

지금 레퍼런스 상세 화면(`reference_detail_screen.dart`)의 메모 칸은 순수
텍스트 `TextField`입니다(`ReferenceItem.memo: String?`). 5단계는 이걸
리치텍스트로 바꾸는 것이 목표입니다: 글자색·형광펜(배경색)·굵게/기울임/
밑줄 같은 서식, 링크, 목록, 정렬.

## 범위

**이번 스펙은 "레퍼런스 메모"만 다룹니다.** CLAUDE.md의 "무드보드 추가
제안" 표에 있던 "무드보드용 가벼운 주석"(카드 위에 짧은 메모를 다는
기능)은 **이번에 포함하지 않습니다** — 사용자가 명시적으로
"레퍼런스 메모만 먼저"를 골랐습니다. 저장 구조도 서로 다른 물건이라
(하나는 레퍼런스에 딸린 값, 하나는 무드보드 카드에 딸린 값), 나중에
따로 브레인스토밍합니다.

## 결정된 것

1. **리치텍스트 편집기는 `flutter_quill` 패키지를 씁니다.** 요구된
   기능(색·형광펜·서식·링크·목록·정렬)을 대부분 기본으로 지원합니다.
   직접 만드는 것은 검토했지만 채택하지 않았습니다 — 이미 검증된
   패키지가 있는데 같은 것을 다시 만들 이유가 없습니다.
2. **저장 형식은 Delta(JSON)입니다.** `flutter_quill`의 표준 문서
   표현입니다. `memo` 칼럼은 타입(TEXT)은 그대로 두고, **안에 들어가는
   내용의 뜻이 바뀝니다** — "순수 글자"에서 "서식이 붙은 JSON"으로.
3. **저장 구조 v4 마이그레이션이 필요합니다** (`schemaVersion` 3 → 4,
   이번이 v4를 쓰는 첫 변경입니다). 기존 메모(순수 텍스트)를 최소
   Delta로 감싸서 새 편집기로 열어도 그대로 보이게 만듭니다.
4. **검색은 이번에 손대지 않습니다.** Delta JSON 안에도 실제 글자가
   `"insert":"찾는 낱말"` 형태로 그대로 부분 문자열로 남아있어서, 지금의
   SQL 부분 일치 검색(`_containsText`)이 대체로 계속 동작합니다. 완벽한
   보장은 아니지만, 문제가 실제로 나타나면 그때 고칩니다(미리
   최적화하지 않는다는 이 프로젝트 원칙).

## 데이터 마이그레이션 (v3 → v4)

`lib/data/app_database.dart`에 `_upgradeToVersion4(Migrator m)`을
추가합니다. 표 구조 자체(칼럼 추가/삭제)는 안 바뀌므로 `addColumn` 같은
것은 없고, **있는 값을 다시 써주는 것**이 전부입니다.

```
memo가 null이 아닌 모든 레퍼런스에 대해:
  meomo = '[{"insert": "<기존 memo 값>\n"}]'  (JSON 이스케이프 처리 포함)
```

`from < 4`로 감쌉니다(부등호 규칙 — 옛 버전에서 여러 단계를 한 번에
건너뛰는 사용자를 위해). `memo`가 null이면 손대지 않습니다(빈 메모는
그대로 빈 메모입니다).

### 마이그레이션 테스트

`test/data/migration_v3_to_v4_test.dart`(새 파일)를 만듭니다. 기존
`migration_v1_to_v2_test.dart`/`migration_v2_to_v3_test.dart`와 같은
방식 — 옛 구조의 진짜 sqlite 파일을 만들어놓고 지금 앱으로 열어봅니다.
최소한 이 다섯을 확인합니다.
- 앱이 켜지는지
- 순수 텍스트였던 기존 메모가 안 사라지는지
- 마이그레이션 뒤 그 메모가 **유효한 Delta JSON**으로 바뀌어 있고, 새
  편집기로 열면 원래 글자가 그대로 보이는지
- 두 번 열어도 중복/깨짐이 없는지 (멱등성)
- **v1·v2에서 곧장 v4로 건너뛰어도** 되는지 (v2→v3처럼 이번에도
  중요한 케이스입니다)

## 편집 화면

`lib/widgets/rich_memo_editor.dart`(새 파일) — `flutter_quill`의
편집창 + 툴바(굵게·기울임·밑줄·글자색·형광펜(배경색)·순서 있는/없는
목록·링크·정렬)를 감싼 위젯 하나입니다.

- 입력: 지금 메모의 Delta JSON(`String?`, null이면 빈 문서로 시작)
- 출력: 바뀐 Delta JSON을 콜백으로 알림(`ValueChanged<String>` 같은 형태)
- `reference_detail_screen.dart`는 이 위젯에 값만 넘기고 받은 값을
  저장하기만 합니다. 편집기 내부 동작(툴바 배치, 커서 상태 등)은 이
  위젯 밖으로 새지 않습니다 — 지금 프로젝트의 "컨트롤러/위젯 분리"
  패턴과 같은 경계입니다.
- `reference_detail_screen.dart`의 기존 `TextEditingController
  _memoController`와 그걸 쓰는 저장 로직(157~185번째 줄 부근)을
  걷어내고 이 위젯으로 교체합니다.

## 목록 카드 미리보기

`lib/widgets/reference_card.dart`가 지금 `item.memo`를 그대로 잘라
보여주는데(212~215번째 줄), Delta JSON을 그대로 보여주면
`{"insert":...}` 같은 글자가 노출됩니다.

`lib/utils/rich_text_memo.dart`(새 파일, 순수 함수)를 만듭니다.

```dart
/// Delta(JSON) 문자열에서 서식을 뺀 순수 글자만 뽑아냅니다.
/// 못 읽는 값(옛날 순수 텍스트가 마이그레이션을 못 탄 경우 등)이면
/// 원래 글자를 그대로 돌려줍니다 — 미리보기가 아예 안 뜨는 것보다 낫습니다.
String plainTextFromMemo(String? memo)
```

`reference_card.dart`는 `item.memo`를 직접 자르는 대신 이 함수를 거친
결과를 자릅니다. 화면 없이 테스트할 수 있는 순수 함수라
`test/utils/rich_text_memo_test.dart`로 촘촘히 확인합니다(정상 Delta,
빈 값, 깨진 JSON, 마이그레이션 전 순수 텍스트가 실수로 남아있는 경우).

## 테스트 전략

- `rich_text_memo.dart` — 단위 테스트(화면 없음)
- `migration_v3_to_v4_test.dart` — 위 다섯 가지
- `rich_memo_editor.dart` — 위젯 테스트로 "값을 넣으면 보이는지",
  "타이핑하면 콜백이 불리는지" 정도만. **서식 버튼 하나하나(굵게, 색
  고르기 등)가 실제로 먹는지는 위젯 테스트로 못 잡습니다** — 이
  프로젝트에서 반복된 패턴(웹뷰, window_manager와 같은 사정)과 달리
  이번엔 플러그인 문제가 아니라 "그림으로 확인해야 하는 상호작용"이라
  그렇습니다. **앱을 켜서 눈으로 확인**합니다.
- `reference_detail_screen.dart`의 기존 위젯 테스트(저장 흐름 등)는
  메모 칸이 `RichMemoEditor`로 바뀌는 것에 맞춰 손봅니다.

## 새로 나온 개념 (PR 본문에 설명 예정)

- **Delta** — `flutter_quill`(그리고 원래 Quill.js)이 서식 있는
  글을 표현하는 JSON 형식입니다. "이 글자를 넣어라" "이만큼 굵게 해라"
  같은 명령들의 목록으로 문서를 나타냅니다. 순수 텍스트보다 복잡하지만,
  색·목록·링크 같은 것을 다 담을 수 있습니다.
- **저장 구조 마이그레이션에서 "칼럼 추가"와 "값 다시 쓰기"의 차이** —
  이번 v4는 새 칸을 추가하는 게 아니라, 있는 칸의 값을 새 형식으로
  다시 씁니다. 그래서 `addColumn` 대신 `update`를 씁니다.
